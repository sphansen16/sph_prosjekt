# Weather Data Experiment

A small Python project I made while testing GitHub and learning more about working with data.

This repository is mostly an experiment. I wanted to learn how repositories work, how files are organized, how commits work, and how Python projects can be uploaded and maintained on GitHub.

The project itself is a simple weather-data program. It doesn't do anything particularly impressive, but it was a useful way to experiment with Python and GitHub.

## About the project

The original idea was to make a small program that could store and display weather information.

For example, the program can work with information such as:

* Temperature
* Wind speed
* Humidity
* Weather conditions
* Location
* Date and time

At the moment, most of the data is manually entered rather than collected from an API.

The reason for this is that I wanted to focus on learning Python first instead of spending most of the time figuring out how APIs work.

## Why I made this

This is basically a GitHub test project.

I'm still learning how GitHub works, so I wanted somewhere to experiment with:

* Repositories
* Commits
* Branches
* Python files
* README files
* Project structure
* Version control
* Editing files directly on GitHub

Some of the files in this repository might therefore look unnecessary. That's intentional.

I wanted to have a small project where I could try different things without worrying too much about breaking something important.

## Project structure

The project currently looks something like this:

```text
weather-project/
│
├── README.md
├── weather.py
└── notes.txt
```

The `weather.py` file contains the main Python code.

`notes.txt` is just a place where I wrote down some ideas and things I want to try later.

The README is mostly here because I wanted to test how GitHub displays Markdown.

## What I learned

While making this project, I learned a little more about how Git works.

One thing I found interesting was that Git doesn't just save the newest version of a file. It also keeps a history of changes.

That means you can look back at previous versions of a project and see what changed.

I also learned that commit messages are quite useful when working on a project.

Instead of simply writing:

> update

it's better to write something that actually explains what changed.

For example:

> Added temperature conversion

or:

> Fixed incorrect wind speed calculation

This makes the history much easier to understand later.
